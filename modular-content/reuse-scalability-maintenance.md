# Notes on Reuse, Scalability, and Maintenance

## Reuse

The main pieces of content we would end up reusing across multiple places in our guidebook would likely be the operating hours, so that has been broken out into a separate section to allow it to easily plug into different areas of the guidebook. As for other reusable aspects, the next would be the wineries' maps, so I've added a module that just includes the Austin Winery's map and address to allow it to be entered into other shortform content like a quick-reference page or pamphlets.

## Scalability

Editing the wineries with more in-depth information can easily be done through our structure: for instance, developing the location overview would just require editing the location-overview.md file as opposed to the main document. Adding a new wine to the catalogue would be its own separate file containing its tasting notes and price. Any added section could simply be dropped into the respective winery folder, as opposed to editing the main file. Additionally, as the guidebook grows, having individual sections allows us to add metadata that would benefit users searching for wineries with specific aspects (price range, location, accessibility).

## Maintenance

Updating information on the wineries would be simple, as writers can update just the relevant section when changes occur like operating hours changes or price shifts. Regular reviews would be conducted annually to ensure accuracy.
